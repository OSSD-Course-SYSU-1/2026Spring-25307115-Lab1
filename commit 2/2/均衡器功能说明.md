# 均衡器功能新增说明

## 一、功能概述

本次更新为音频播放器应用新增了 **10段参数均衡器（Parametric Equalizer）** 功能，用户可对 31Hz ~ 16kHz 共10个频段进行独立增益调节（范围 -12dB ~ +12dB），并内置8种音效预设，实现对不同音乐风格的快速适配。

---

## 二、新增文件

| 文件路径 | 说明 |
|---------|------|
| `entry/src/main/ets/components/EqualizerComponent.ets` | 均衡器 UI 组件，包含面板、预设选择、10段滑块 |
| `entry/src/main/ets/utils/EqualizerController.ets` | 均衡器控制器，负责频段管理、预设逻辑及 PCM 数据处理 |

## 四、功能详情

### 4.1 10段均衡频段

| 序号 | 中心频率 | 标签 |
|:---:|:------:|:---:|
| 0 | 31 Hz | 31 |
| 1 | 62 Hz | 62 |
| 2 | 125 Hz | 125 |
| 3 | 250 Hz | 250 |
| 4 | 500 Hz | 500 |
| 5 | 1000 Hz | 1K |
| 6 | 2000 Hz | 2K |
| 7 | 4000 Hz | 4K |
| 8 | 8000 Hz | 8K |
| 9 | 16000 Hz | 16K |

每段增益范围：**-12 dB ~ +12 dB**，步进 1 dB。

### 4.2 内置预设

| 预设名称 | 说明 |
|---------|------|
| 默认（FLAT） | 所有频段 0 dB，无修饰 |
| 流行（POP） | 中高频略提升，低频微降 |
| 摇滚（ROCK） | 高低频增强，中频凹陷（V型曲线） |
| 爵士（JAZZ） | 低频温暖，高频明亮 |
| 古典（CLASSICAL） | 宽广频率响应，高低频略提升 |
| 人声（VOCAL） | 500Hz ~ 4kHz 中频突出 |
| 低音增强（BASS_BOOST） | 低频频段大幅提升 |
| 高音增强（TREBLE_BOOST） | 高频频段大幅提升 |

### 4.3 信号处理算法

- 采用 **二阶 IIR Biquad 滤波器**（Peaking EQ 类型）
- 每个频段独立计算滤波器系数，使用 Direct Form I 结构
- 对 PCM S16LE 数据逐帧逐通道处理，处理后的数据原地写回
- 支持双声道（立体声）独立处理，滤波器状态在切换预设或关闭时自动重置

### 4.4 UI 交互

- 控制区显示"均衡器"按钮，点击展开/收起均衡器面板
- 面板顶部：标题 + 启用/禁用开关 + 关闭按钮
- 预设行：横向滚动，点击即应用对应预设
- 滑块区：10个竖向滑块（通过 `rotate(-90°)` 实现），实时显示当前增益值（正值绿色、负值红色、零值白色），底部标注频率及 Hz 单位

## 五、播放路径集成

### 5.1 整体架构

项目存在两条音频播放路径，均衡器对两条路径均做了适配：

| 播放路径 | 适用格式 | 均衡器接入方式 |
|---------|---------|---------------|
| AVPlayer | MP3 / FLAC | 通过 `audioEffectMode` 系统音效模式联动 |
| AudioRenderer | PCM | 在 `writeData` 回调中直接对 PCM 缓冲区做滤波处理 |

### 5.2 PlayerController 统一调度

`PlayerController` 作为播放控制的中枢，持有 `EqualizerController` 实例，并在以下时机完成均衡器的注入：

1. **初始化阶段**（`init` 方法）：创建 AVPlayerController 后立即调用 `setEqualizer()` 注入均衡器实例。
2. **格式切换阶段**（`changeType` 方法）：当切换到 PCM 格式时，AudioRenderer 初始化完成后同样调用 `setEqualizer()` 注入同一个均衡器实例，确保两条路径共享均衡器状态。
3. **预设切换**（`applyEqPreset` 方法）：调用 `eqController.applyPreset()` 更新频段增益后，根据当前播放路径通知对应的播放器重新应用效果。
4. **启用/禁用**（`setEqEnabled` 方法）：切换均衡器开关状态，并同步到当前活跃的播放器。

### 5.3 AVPlayer 路径 — 系统音效联动

```
AVPlayerController.setEqualizer(eq)
       │
       ▼
applySystemAudioEffect()
       │
       ▼
avPlayer.audioEffectMode = EFFECT_DEFAULT / EFFECT_NONE
```

- 当均衡器启用时，设置 `audioEffectMode` 为 `EFFECT_DEFAULT`，由系统音效引擎处理音频增强。
- 当均衡器关闭时，设置为 `EFFECT_NONE`，音频直通不做处理。
- 异常处理：调用 `audioEffectMode` 赋值时使用 `try-catch` 包裹，防止系统 API 异常导致崩溃。

### 5.4 AudioRenderer 路径 — PCM 实时处理

```
AudioRenderer writeData 回调触发
       │
       ▼
fileIo.readSync() 读取 PCM 数据到 buffer
       │
       ▼
eqController.processPcmData(buffer, bufferLength)
       │
       ▼
10段 Biquad 滤波器逐段处理 → 原地写回 buffer
       │
       ▼
AudioRenderer 播放处理后的 buffer
```

关键实现细节：
- `setEqualizer()` 被调用时，同步设置采样率（48000Hz）和声道数（2），确保滤波器系数计算正确。
- `processPcmData()` 内部先检查均衡器是否启用、是否存在非零增益，避免不必要的计算开销。
- 对增益为 0 的频段自动跳过，进一步优化性能。
- 处理完成后对样本做 ±32767 限幅（S16LE 范围），防止溢出产生爆音。
- 滤波器状态（`filterStates`）跨 buffer 保持连续性，避免分段处理产生的拼接伪影。

## 六、核心算法说明

### 6.1 Biquad Peaking EQ 滤波器系数计算

采用 Audio EQ Cookbook（Robert Bristow-Johnson）标准公式：

```
A     = 10^(gainDb / 40)       // 增益的平方根（线性）
Q     = 1.414                   // Butterworth Q 值 (√2)
w0    = 2π × frequency / sampleRate
alpha = sin(w0) / (2Q)

b0 =  1 + alpha × A
b1 = -2 × cos(w0)
b2 =  1 - alpha × A
a0 =  1 + alpha / A
a1 = -2 × cos(w0)
a2 =  1 - alpha / A

归一化后: [b0/a0, b1/a0, b2/a0, a1/a0, a2/a0]
```

### 6.2 Direct Form I 差分方程

```
y[n] = b0 × x[n] + s0
s0   = b1 × x[n] - a1 × y[n] + s1
s1   = b2 × x[n] - a2 × y[n]
```

其中 `s0`、`s1` 为滤波器状态变量，跨 buffer 保持连续。

## 八、总结

本次新增的均衡器功能覆盖了从 UI 交互到音频信号处理的完整链路：

1. **UI 层**：`EqualizerComponent` 提供可视化的10段均衡调节界面与8种预设模式。
2. **控制层**：`PlayerController` 统一调度，确保均衡器状态在 MP3/FLAC/PCM 三种格式切换时保持一致。
3. **算法层**：基于 Biquad IIR 滤波器的 Peaking EQ 实现，对 PCM 数据进行实时逐样本处理，支持双声道独立滤波。
4. **播放器适配**：AVPlayer 路径通过系统音效模式联动，AudioRenderer 路径通过 `writeData` 回调直接处理 PCM 缓冲区。

整体设计遵循 MVC 模式，`EqualizerController` 作为 Model 层独立于 UI，可被任意播放路径复用，具备良好的可扩展性。
